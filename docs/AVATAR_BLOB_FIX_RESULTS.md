# Avatar and form-photo Blob fix: results

**Changed.** `lib/blob/stores.ts`: `blobStore("avatars" | "formPhotos")` returns `{ token, access: "public" }` from `BLOB_PUBLIC_READ_WRITE_TOKEN`; `tokenForBlobUrl` picks the delete token by the URL's host (public host: public token; private host: legacy `BLOB_READ_WRITE_TOKEN`; any other host or store id: 400; unset variable: 503 naming it). Avatar routes, `deleteAvatarBlobs`, the trusted store host, `/api/blob/upload` (token passed to `handleUpload`) and `/api/blob/delete` all go through it. New error code `store-access-mismatch` (502) in avatar and form-photo routes and clients: friendly text for users, "Blob store access mode does not match" added in development only. The private token is declared as legacy and is only used to delete older files.
**Variable to set in Vercel (Preview and Production):** `BLOB_PUBLIC_READ_WRITE_TOKEN` (the store connected with the prefix BLOB_PUBLIC; the store must be PUBLIC and that cannot be changed). Make a **new deployment** after changing environment variables. `BLOB_PUBLIC_STORE_ID` and `BLOB_PUBLIC_WEBHOOK_PUBLIC_KEY` are not used. Preview and Production share this store for now (see DEPLOYMENT.md).
**Matched error text.** `@vercel/blob` 2.8.2 has NO access-mismatch error class: only a `bad_request` answer passes the service's text through (as "Vercel Blob: <text>"); every other failure becomes a fixed message. The matcher (`lib/blob/errors.ts`) looks for public/private access plus a store in that text, e.g. "Vercel Blob: Cannot use public access on a private store. The store is configured for private access." That wording is NOT confirmed against the live service (no real calls were made); if a mismatch shows as `store-failed`, copy the server log line and tighten the pattern.
