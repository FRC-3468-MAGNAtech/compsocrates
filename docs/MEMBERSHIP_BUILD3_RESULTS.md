# Memberships build 3: results (applications for both programs, one Join / Apply screen, no-team accounts, personal practice, share on join)

Branch `release-prep`. Nothing was deployed or run against a real project. Rules are written, not deployed. The proof for personal practice was written FIRST (`data/ftc/personal-practice.emulator.test.ts`): a no-team account with no FTC profile reads a published `origin == "api"` FTC library match through the `||` short-circuit, and the root library, with NO rule change. So personal practice was built.

## What exists
- ONE Join / Apply screen (`components/team-setup/team-setup-screen.tsx`: `TeamSetupView` draws, `TeamSetupScreen` reads). FTC wording is the reference (the "moved from the previous site" sentence is gone); tab "Apply for a team"; same words word for word in `/frc` and `/ftc` (parity test renders every state, guard test forbids a second one). `TeamEnrollmentScreen`/`Fields`, `TeamSetup`, `JoinAnotherTeam`, the sign-up team step, `ProgramData.enrollment` and the FTC client `createTeam` are deleted. `ProgramGate` and the shell render the one screen.
- Join requests persist in BOTH programs, read ONCE per visit (`POST /api/team/my-join-requests`, no listener), Cancel in both (`POST /api/team/cancel-request`), several pending (one per team, max 5, same team again = 409). FTC keeps a server-only pointer `programs/ftc/joinRequestPointers/{uid}` = `{ entries: [{ teamId, requestId, status }] }` (no names, emails, codes; the request document stays the truth, so the older client approve/deny batches are noticed). Deviation: a denied or canceled entry stays as a one-line "last closed" status (for the shared notice) and goes when a new request to that team is filed.
- Applications for both programs: `/api/applications` takes a REQUIRED `program`, answers 403 `applications_closed` unless `teamCreationEnabled` is true, uses the program's own collections, number field and blocks. Approval (`lib/server/application-decisions.ts`, one implementation): team + owner; pointer set only when the account has no active team here; with memberships ON a VERIFIED owner membership and the 5-team cap (an account with a team keeps its pointer); OFF: as before, incl. 409 `already-member`. `/api/team/create` answers 410. Admin Panel: one Applications panel (program badge, one-time reads + Refresh, no listeners) in both programs' tabs; switch label "Accept team applications" (shown in the FRC panel only: FTC `platformSettings` is still false).
- No-team accounts (ON only): `resolveShellRoute` (`lib/personal/routing.ts`, tested exhaustively, never loops), personal sidebar, `PersonalDashboard`, read-only Profile and a note in Account (FTC no-team settings stay on the device), Admin Panel for a platform owner (claim read from the token; platform tabs only). OFF: exactly as before.
- Personal practice (ON only): `personalPractice/{uid}/sessions|entries|state` (FTC under `programs/ftc/`), no `teamId` key, one-time reads, the shared official library, accuracy by `practiceOutcome` (null with no score). Share on join: opt-in prompt on the dashboard (once) and a button on Practice Scouting; `POST /api/team/share-practice` copies completed sessions + entries (batches of 400, 3,000 writes per call, resumes, deterministic ids, marker `personalPractice/{uid}/state/share`, never deletes the private copy).

## New fields, collections, routes (person data for the deletion session)
`teamApplications`, `applicationPrivate`, `applicationBlocks`, `platformAuditLog` now also under `programs/ftc/` (application documents carry applicant name and email, and a new `program` field); `joinRequestPointers` (FTC); `personalPractice` (sessions and entries carry `scoutName`, `uid`); `state/share` marker. Team documents from applications carry `applicationId`. Routes: my-join-requests, cancel-request, share-practice.

## Manual check (TEST accounts only)
Switch OFF: /frc and /ftc Join and Apply side by side look identical; Apply says closed with the setting off; nothing else changed. ## Rollback
Switch off (`membershipsEnabled`), set `teamCreationEnabled` false; revert the commits; redeploy the saved ruleset to reopen the FTC create rules. New collections can stay.
