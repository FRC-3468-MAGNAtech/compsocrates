# Memberships build 2: results (join, leave, removal, roles, roster seam, team switcher, My teams, Past Team Members, Verify admins)

Branch `release-prep`. Nothing was deployed or run against a real project. Everything is behind `appSettings/global.membershipsEnabled` (missing = OFF): OFF, the app, the old join routes and the FTC client batches behave as before and the new routes answer 404 `memberships_disabled`.

## What exists
- Server (one implementation for both programs; `ProgramConfig.membership.flows` is the data): `lib/memberships/flows.ts` (pure rules), `lib/server/membership-flows.ts` (join lookup, request, approve/deny, leave, remove, role edit, verified-membership halves), `lib/server/verify-admins.ts`, `lib/server/membership-route.ts` (20 s deadline = 504 `timeout`, quota code 8 = 503 `quota_exceeded`, 503 `server_not_configured`). Routes: `/api/team/join-lookup`, `membership/request-join`, `membership/decide`, `leave`, `member/remove`, `member/access`, `/api/platform/verify-admins`. `membershipsEnabled` (boolean only) is in `/api/public/config`.
- Verified memberships: approval, rejoin (same document, `joinedAt` kept, `rejoinedAt`), FRC team creation and application approval, ownership transfer, and the owner's Verify admins. Role at approval is the server's: the requested role only if the team's `allowMemberRoleChoice` is `true` and the role is a valid non-admin one (`team-coach` excluded), else Match Scout. The 5-team limit counts a pointer without a membership as one.
- Roster seam `lib/team-roster.ts` + `lib/server/team-roster.ts`: OFF = today's single `users where teamId ==` read (query-count tests); ON = plus one cached memberships read per team per page load, no listener; denied = users only.
- UI: `TeamSwitcher` (sidebar and top bar; the old one is `FieldTeamSwitcher`), "Switching…" hold then `key={teamId}` remount, Join another team (role select only when the server says the team allows it), Remove member, role edits through the route, requested role on the pending card, Team Settings switch, My teams with Leave, Past Team Members (collapsed, admins; unverified admins see "Ask the platform owner to verify team admins to see past members"), Admin Panel > Verify admins (platform owner).
- FTC "no team": an EMPTY team id counts as no team in `ftc_sameTeam`, new `ftc_hasTeam()`, `ProgramGate`, the request-join route and the lobby route (tests in `lib/ftc/no-team-gates.test.ts`, emulator tests).

## Findings (reported, not changed)
- FRC approve while OFF (`processJoinRequest`): the request document is client-written, so `requestedRole` is requester-controlled. `normalizeLegacyRole` maps it to a valid role id (a forged "coach" becomes `team-coach`; anything unknown becomes Match Scout) and `isTeamAdmin` is always false, so it can grant any role id, never admin or owner. Clamping would mean applying `resolveApprovedRole` there (a behaviour change while OFF).
- gRPC vs REST: commit 7fba154 (2026-11-15) moved only the FTC request-join route to the REST client because "gRPC stalled on its first call" on the host; the host is not named in the commit or `lib/firebase/admin.ts`. The REST client supports transactions, but every existing transactional route (switch, create, transfer, approve) uses gRPC, as do the new ones. Unknown whether the stall exists in production; the 20 s deadline turns a stall into 504 `timeout` instead of a hung request.
- No shared draft detection exists (only per-page `beforeunload` in the form builder and Credits), so there is no "unsaved changes" prompt before a switch. Left for later.
